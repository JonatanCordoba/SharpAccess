# SharpAccess Sample API

This project is a non-packable, Windows-only test host for the SharpAccess source tree. It is not included in `SharpAccess.Core`, `SharpAccess.Sqlite`, or `SharpAccess.Postgres` packages.

## First run

From PowerShell 7 on Windows with the SDK selected by `global.json`:

```powershell
dotnet restore SharpAccess.sln --locked-mode
dotnet run --project samples/SharpAccess.SampleApi/SharpAccess.SampleApi.csproj
```

The first run opens a console setup wizard before ASP.NET Core starts. It accepts or generates:

- JWT signing material;
- opaque-token hashing material;
- a password pepper;
- a dedicated rate-limit partition key;
- administrator, manager, and standard-user test credentials;
- optional Google-compatible OpenID Connect credentials.

Account passwords must contain 15 to 256 characters, including at least one letter and one digit, and must not contain the account email name before `@`. For example, a password for `user@test.local` must not contain `user`, regardless of casing. Leaving an account-password prompt blank generates a compliant password. The Google client secret must be the actual secret issued by the provider and is never generated by the sample.

The completed setup is serialized into a generic credential named `SharpAccess.SampleApi.LocalSettings` in Windows Credential Manager for the current Windows user. Secret values are never written to tracked settings, static files, browser storage, or API responses. Environment variables continue to override stored values for automated tests. If an older stored entry contains account passwords that do not satisfy the current SharpAccess policy or account-derived password rule, the interactive host removes that entry and reruns setup before startup.

Open `http://localhost:5000` after startup. The browser console uses local HTML, CSS, and vanilla JavaScript with a Material Design-inspired layout. It contains login, users, tenants, roles, permissions, modules, audit, and sample-settings sections.

## Google OpenID Connect

Create a Google OAuth 2.0 client of type **Web application**. Add this exact authorized redirect URI when the sample uses its default port:

```text
http://localhost:5000/auth/oauth/google/callback
```

When using another `APP_PORT`, replace `5000` with that port. The scheme, hostname, port, and path must match exactly. If the Google app audience is in Testing, add the Google account you will use as a test user in the Google Auth Platform configuration.

The browser starts authentication by navigating to the SharpAccess challenge endpoint with a bounded local return path. After Google redirects to the configured callback, SharpAccess places a short-lived one-time `oauth_code` in the local URL fragment. The sample removes that fragment from the address bar, exchanges the code through `POST /auth/oauth/google/exchange`, and then reloads using the resulting secure refresh session.

## Seed data

The Development host creates one verified administrator through the explicit local seed API, then uses SharpAccess HTTP endpoints to register and verify a tenant manager and a standard user. It also creates:

- permission-backed sample module roles;
- a `Sample Tenant Manager` role;
- `Northwind Test Lab` and `Contoso Sandbox` tenants;
- tenant memberships for the manager and standard user.

The process is idempotent. It calls the same `/auth`, `/admin`, and `/tenants` endpoints used by the browser rather than reaching into provider internals.

## Reset

Stop the application before resetting local state.

```powershell
# Replace the current-user Credential Manager entry and run setup again.
dotnet run --project samples/SharpAccess.SampleApi -- --reset-local-setup

# Remove the local SQLite database and reseed it.
dotnet run --project samples/SharpAccess.SampleApi -- --reset-sample-data
```

Both flags may be supplied together.

## Framework and package boundaries

The browser does not use React, Angular, Vue, Svelte, jQuery, Bootstrap, Tailwind, a CDN, or a package-managed frontend framework. `SampleModule` is a sample-only POCO whose entries map to existing SharpAccess permissions through ordinary roles. The sample project remains `IsPackable=false`, and package-structure tests protect that boundary.
